 Migração: Pipeline de Call Reports — 
 Mac/Claude Code → Contabo VPS + DeepSeek +
  GCS

 Context

 O pipeline atual corre num Mac local via
 launchd às 04:00 e depende do Claude Code
 (este CLI) para fazer a orquestração: ler
 logs, decidir o que correr, chamar a
 Anthropic API para gerar analysis.json, e
 disparar build_report.py + send_email.py.
 Os ~9.7 GB de dados acumulados (áudios
 MP3, transcrições, JSON, PDFs) vivem em
 agents/<X>_Call_Report/data/<dd-mm-yyyy>/
 no disco do Mac.

 Problemas que esta migração resolve:
 - Dependência do Mac ligado às 04:00 e do
 Full Disk Access do macOS.
 - Custo elevado da Anthropic API (~$15–25
 por report × 6 agentes/dia).
 - Storage local a crescer sem teto (já em
 9.7 GB).
 - Orquestração via AI agent (não
 determinística, difícil de debugar).

 Resultado pretendido:
 - VPS Contabo a correr um único script
 Python determinístico via cron.
 - Análise gerada pela DeepSeek API
 (deepseek-v4-pro, ~10–30× mais barato que
 Claude Opus).
 - Google Cloud Storage como fonte única da
  verdade — VPS só usa disco local como
 cache temporário durante execução.
 - Email Gmail SMTP mantém-se (sem mudanças
  no endereço de envio).

 VPS Contabo — specs recomendadas

 Recurso: Plano
 Valor mínimo: Contabo VPS XS (~€4.50/mês)
 Recomendado: Contabo VPS S (~€6.99/mês)
 ────────────────────────────────────────
 Recurso: vCPU
 Valor mínimo: 4
 Recomendado: 4
 ────────────────────────────────────────
 Recurso: RAM
 Valor mínimo: 6 GB
 Recomendado: 8 GB
 ────────────────────────────────────────
 Recurso: Disco
 Valor mínimo: 100 GB SSD
 Recomendado: 75 GB NVMe (mais rápido)
 ────────────────────────────────────────
 Recurso: OS
 Valor mínimo: Ubuntu 24.04 LTS
 Recomendado: Ubuntu 24.04 LTS
 ────────────────────────────────────────
 Recurso: Localização
 Valor mínimo: Nuremberg ou Düsseldorf
 Recomendado: Indiferente — latência
   aceitável para HubSpot/OpenAI/DeepSeek

 Justificação: workload é CPU-light
 (Whisper e DeepSeek são API calls; só
 ffmpeg consome CPU em picos). Peak de RAM
 expectável: ~2 GB. Disco temporário: ~3
 GB/dia. VPS S dá margem confortável e
 custa quase igual ao XS.

 deepseek_analysis.py (novo)

 - Cliente OpenAI-compatible apontado a
 https://api.deepseek.com.
 - Função analyze(transcripts: list[dict],
 context: dict, agent: dict) → dict que
 devolve o analysis.json com as 5 chaves do
  CLAUDE.md (overall_assessment,
 what_agent_does_well, critical_weaknesses,
  call_summary, priority_coaching_actions).
 - Prompt em português (Portugal), inclui
 regra real-estate (sem cross-sell entre
 developments) condicionalmente para
 David/Sandra/Zé/Joana.
 - Modelo: deepseek-v4-pro (1M context —
 cabem facilmente 50+ transcrições +
 context histórico).
 - Usa response_format JSON para garantir
 output estruturado.
 - Inclui prompt cache: o system prompt +
 agent context são marcados como cacheable
 (cache hit reduz preço a 1/10).

 Tratamento de falhas

 - Pipeline crash global: run_pipeline.py
 envolve main() em try/except. Em caso de
 exceção não capturada, envia email para
 PIPELINE_FAILURE_EMAIL com últimas N
 linhas do log + traceback.
 - Falha por agente: cada process_agent()
 corre em try/except próprio. Falha de um
 agente não bloqueia os outros. Erro fica
 no log e é incluído no email de resumo.
 - Falha de API (HubSpot/Whisper/DeepSeek):
  retry com backoff exponencial (3
 tentativas) já existente em
 daily_fetch.py. Para DeepSeek, adicionar
 retry no novo deepseek_analysis.py.
 - Falha de upload GCS: retry 3x. Se falhar
  definitivamente, mantém ficheiros locais
 no /tmp/pipeline/<date>/ (não fazer
 cleanup) e alerta.
